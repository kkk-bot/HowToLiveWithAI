# 先认识 AI

先理解几个会影响使用的概念，再选择工具。模型原理可以按兴趣深入；开始使用不要求先学完数学或背产品名称。本章是入门解释，具体产品能力仍需查说明并核对实际结果。

<a id="entry-1.1"></a>

## 1.1 模型与应用是什么

| 词 | 入门解释 |
| --- | --- |
| 生成式 AI | 根据输入生成文字、图像等内容；AI 还包含分类、预测等其他用法 |
| 大语言模型 | 从大量数据学习语言模式，用于生成、摘要、问答等任务 |
| 提示词 | 交给模型的请求、材料与要求，可以持续修改 |
| 上下文窗口 | 模型一次能处理的信息范围，不等于永久记忆 |
| 幻觉 | 回答看起来合理，内容却错误或缺少事实依据 |
| Agent | 结合模型与工具，按目标执行步骤的应用；需要检查权限与结果 |

这些解释参考 [R25](../docs/附录D-研究与官方资料.md#r25)、[R26](../docs/附录D-研究与官方资料.md#r26) 的相关条目。模型和应用也要区分：模型提供生成能力，应用增加界面、资料读取或其他工具；某个应用能做什么，还要看它实际提供的功能。

许多自回归语言模型会根据已有内容逐步预测后续 token。token 是文本处理单位，可能是字、词或词的一部分，并不固定等于一个汉字。回答流畅说明它能组织语言，事实是否成立需要另查。更详细的生成与训练说明见 [A.1](../docs/附录A-进阶原理.md#a-1)。

### 从一封邮件分清模型、应用和工具

假设你要把一封公开的活动通知改写成提醒。模型可以组织语句，应用负责接收输入、展示回答；如果应用能读取附件、查询日历或发送邮件，还涉及额外工具。看到“提醒已经写好”，只说明有了文字草稿。是否创建日历、是否发送给别人，要查看实际操作记录。

这一区分能帮助你选择用法。只是想改一句话，普通对话就可能够用；需要统计表格，要有实际计算和可核对的输入；需要更新日历，则要确认工具能访问哪个日历、写入什么。先问任务需要哪些环节，再检查应用是否提供这些环节，比从一个“万能 AI”的想象开始更清楚。

### 常见的四种使用方式

| 方式 | 你交给它什么 | 自己要看什么 |
| --- | --- | --- |
| 起草与讨论 | 目的、受众、限制 | 观点是否适合，事实有没有补造 |
| 材料整理 | 可使用的原文与字段 | 有没有漏掉、读错或超出原文 |
| 工具辅助 | 数据、操作对象与步骤 | 是否真的执行，输入和返回是否正确 |
| 学习陪练 | 学习材料、自己的尝试 | 离开回答后能否解释和完成 |

同一个任务可以组合这些方式，例如先整理活动要求，再讨论通知结构，最后人工确认并发布。先分清“文字建议”和“实际执行”，就能知道哪里需要自己接手。这里的分类用于入门，不是对所有产品功能的穷尽。

“多模态”通常指能处理文字、图像、音频等不同形式的输入或输出。它不意味着每种材料都读得准：照片中的小字、遮挡和图表单位仍要抽查。第一次可以给一张答案明确的图片，让应用说明看到了什么，自己对照，然后再考虑复杂材料。

**今天可做：** 选一个自己接触过的 AI 应用，区分它的生成回答、文件读取和计算功能。

**可以怎样检查：** 能说清“模型生成了什么”和“应用额外执行了什么”；不清楚的功能暂时保留未知。

## 1.2 上下文、记忆与幻觉

上下文是模型这次处理的信息范围；应用保存的聊天记录、偏好与记忆功能是另一层机制。普通聊天会影响本次回答，不能据此说模型已经重新训练。训练与微调会调整模型参数，进一步见 [A.3](../docs/附录A-进阶原理.md#a-3)。

回答看起来合理却有错误或缺少依据，常被称为幻觉。日期、出处、人物经历都可能被补造。“它之前知道”也不保证新对话能得到同一背景。因此重要任务要主动提供必要条件，允许它回答“未知”。

上传材料是否保存、谁能访问、是否用于未来训练，需要分别查看服务政策；“这次没有改参数”不能推出“材料不被保存”。依据见 [R25](../docs/附录D-研究与官方资料.md#r25)、[R26](../docs/附录D-研究与官方资料.md#r26)、[R30](../docs/附录D-研究与官方资料.md#r30)。

### 换一段对话，为什么要重新交代背景

想象你先说“帮我写自我介绍”，之后陆续补充“只讲一分钟”“面向社团成员”“不要提学校全名”。你看到的聊天历史，不一定等于应用这次交给模型的全部内容。应用可能截取、压缩或另行保存信息；具体方式因产品而异。

最直接的处理，是在关键修改前整理一份简短的已确认条件：“用途是社团介绍；一分钟；只用我的真实经历；学校名称不公开；这次只改结尾。”让它先复述条件，发现理解错误再开始。这个动作帮助恢复任务背景，但仍不能保证每次都遵守。

可以把资料分成三层：原始材料、你已确认的事实、待核实的猜想。不要把生成答案里的猜测回填成事实，再让后面的回答引用它。例如 AI 先猜某活动免费，下一轮你直接说“给这个免费活动写宣传”，错误就进入了新的输入。

### 一份方便带走的背景卡

```text
我现在要做：给社团新成员写一分钟自我介绍。
已确认：我负责过一次活动通知；愿意帮忙整理资料。
必须满足：只写真实经历，不公开个人联系方式。
尚未决定：结尾是邀请交流，还是说明能提供什么帮助。
这次只做：给两种结尾，说明各自适合的语气。
```

上面是虚构教学材料。背景卡可以保存为普通文字文件；目的在于让你知道哪些信息来自自己，哪些仍是讨论中的选项。它不是给个人生活建立无限档案，也不需要为了获得“更懂你”的回答上传所有隐私。

对于幻觉，重点是安排核对位置。让模型说“我很有把握”没有增加证据；让它给一个来源也只是多了待查线索。涉及日期、出处、数据、定义时，先回到原文。涉及你的偏好时，再问“这真的符合我吗”。两类问题需要不同的检查。

### 能放进长对话，不等于每一处都被用好

一份文件能成功放入上下文，并不能证明回答使用了其中所有相关信息。Liu 等在多文档问答和键值检索实验中，改变相关信息的位置，发现当时测试的模型表现会随位置变化，放在中间的信息往往更难利用。这是针对特定历史模型和任务的结果，不是所有当前工具的统一错误率。见 [R37](../docs/附录D-研究与官方资料.md#r37)。

对日常使用，可以先明确这次要回答的问题，保留原始材料，再整理相关章节与已确认条件；回答引用了哪一段，就回到哪一段核对。整理时也要留意其他位置的例外条件，不能只截取支持自己想法的片段。把重要要求单独列出有助于检查，但不是“放开头就不会错”的保证。

**今天可做：** 给一个小任务写下目标、已确认事实、限制和未知项，换对话时重新提供。

**可以怎样检查：** 先核对 AI 复述的条件；关键事实仍回到原材料检查，不用语气判断真假。

## 1.3 文件、检索与计算工具

应用可能把可处理的内容直接放进上下文，也可能先检索相关片段，再交给模型回答。后一种做法常称为 RAG，即检索增强生成。典型流程是“问题 → 检索材料 → 把相关内容加入上下文 → 生成回答”。一种常见检索方法把问题和材料转成向量，即一组数字表示，用来比较相关性；也可结合关键词等检索方式。见 [R25](../docs/附录D-研究与官方资料.md#r25)、[R29](../docs/附录D-研究与官方资料.md#r29)。

RAG 不是只有文件太大才用，也不能保证每次都找齐相关材料。资料可能读错、检索可能漏掉关键片段、回答可能超出原文。引用存在也不够，还要看原文是否真正支持结论。具体产品怎样处理文件，需要看它的说明和实际结果。

对你的用法：问课程安排、活动要求或文档条款时，让回答附上位置与原文依据，缺失处标为“材料未说明”。能找到原文之后，再自己对照。见 [B.1 材料问答练习](../docs/附录B-练习与模板.md#b-1)。

文字模型可以生成正确的数字与步骤，也可能生成看似合理的错误结果。单看“我运行了代码”这句话，不能确认代码真的执行过。工具调用通常由模型提出调用及参数，再由应用执行工具，把结果返回给模型。见 [R30](../docs/附录D-研究与官方资料.md#r30)。

例如统计一份表格：模型可以帮助写公式或代码，计算器、表格软件或执行环境负责实际计算。核对时要看输入数据、单位、公式、运行结果，以及最终解释是否一致。工具算出数字，也不能替你确认输入和问题设定正确。

对你的用法：重要计算要有可复核的计算记录；做模拟时区分一次运行结果与理论结论。工具不可用时，可以自己用表格或计算器复算。见 [B.1 计算练习](../docs/附录B-练习与模板.md#b-1)。

### 一份通知怎样经过三个环节

虚构材料：“活动于 10 月 17 日下午两点开始，地点是图书馆二层。报名要求见另一份通知。”你问“何时报名截止”，可能先发生读取：应用把文字识别出来；然后发生查找：从现有材料挑选相关段落；最后发生生成：模型组织答案。

只给这段材料，正确的整理应保留“截止日期未在本段写明，需要另一份通知”。如果应用没有拿到第二份通知，就不能补出一个日期。检查时分别问：这句话有没有被读到？所引段落是不是相关的？答案是不是超出了段落？这样可以定位问题，而不只是不断要求“再准确一点”。

当材料很多时，可以先缩小问题，例如“只查报名方式与截止日期，并列出处”，而不是“总结所有资料”。但如果没有找到，结论应是“这次没有找到”，不能立即说整份资料不存在这条信息。需要时自己查看目录、相关章节或向原发布者确认。

### 用一个小表格认识实际计算

下面的数据是虚构的：同学甲买两本书，每本 30 元；同学乙买一本书，价格 25 元。合计应为 2 × 30 + 1 × 25 = 85 元。模型可以解释算式，表格软件或计算器负责实际计算；你负责确认“两本”和“每本”的意思没有读错。

如果输入表有数量、单价、运费三列，还要确认运费是每件还是每单。工具即使正确执行了一个公式，也可能是在执行错误的设定。先明确字段含义，再看公式和数值，最后解释结果。这种分工同样适用于更长的表格：先拿一小部分人工核算，再比较汇总结果。

你不必为了理解这个流程先掌握向量数据库或接口代码。入门需要的是能发现哪一步出了问题；想进一步搭建系统时，再到附录 A 理解 RAG、API 和工具调用。

**今天可做：** 用一段已知答案的短材料做问答，再用简单数字练一次计算。

**可以怎样检查：** 原文位置确实存在且支持结论；计算输入、单位与结果一致。声称执行工具时，要能查看实际返回记录。

### 先判断任务需要哪一种能力

同样是“帮我处理这件事”，背后可能需要完全不同的方法。一个聊天窗口可能同时接入多种功能，但能聊天、能搜索、能读取文件、能操作账号，仍是不同的能力。先看任务缺什么，才方便选择。

| 眼前的问题 | 可以先用什么 | 重点检查 |
| --- | --- | --- |
| 改一段自己写的说明 | 聊天与文本编辑 | 意思、对象和事实有没有被改动 |
| 查一项当前规定或活动安排 | 搜索与原发布页面 | 来源、日期、适用对象及是否已更新 |
| 理解一份指定材料 | 文件读取或检索 | 相关内容是否读到，答案是否得到材料支持 |
| 汇总有明确规则的数字 | 表格、计算器或代码 | 数据范围、单位、公式与异常项 |
| 按固定步骤重复处理 | 现有软件或固定流程 | 每一步的输入、输出和失败处理 |
| 需要根据结果不断选择下一步 | 具备相应工具的 Agent | 实际动作、权限、费用和停止条件 |

虚构情境：你要整理社团活动反馈。写三句总结可以请 AI 起草；计算有效问卷人数可以用表格；确认下次场地是否开放，需要查实际场地信息；发通知则涉及发布权限。没有必要为了完成一句总结，就先授权邮箱和全部文件。

固定流程与 Agent 的区别，可以用整理材料来理解。固定流程是“读取指定表格→按规则检查→生成待确认清单”；Agent 则可能根据发现的问题，自行决定继续找哪份材料、调用什么工具。后者增加了灵活性，也增加了需要观察的步骤。这里借用 [R35](../docs/附录D-研究与官方资料.md#r35) 的区分，例子为本项目改编，不是产品能力保证。

开始时先把一个步骤做清楚。如果普通表格就能完成，不必为使用新名词额外搭系统。之后遇到明确的限制，再考虑增加检索、脚本或自动操作。学会选择简单而够用的方法，本身就是一种技能。

## 1.4 怎样理解 AI 的能力和局限

AI 是否有帮助，要结合具体任务、材料、工具条件和自己能否检查来判断。它可能善于起草、归类或解释某些内容，却在另一些看起来相似的任务上出错。一次演示、榜单分数或他人的成功经历，都不足以推断它能完成你的全部工作。

可以先问：我需要什么结果？材料能不能使用？我有办法核对吗？出错后能不能修正？无法判断的高影响问题，要补可靠材料或请合适的人复核，必要时停止。对照自己的任务比追逐参数大小更有用。

职业写作、客服和咨询研究分别在不同条件下观察效果，不能合成通用提效比例。边界与阅读范围见 [R01](../docs/附录D-研究与官方资料.md#r01)、[R02](../docs/附录D-研究与官方资料.md#r02)、[R03](../docs/附录D-研究与官方资料.md#r03)。评估方法为作者建议，未完成读者实测。

### 把一次“惊艳演示”换成自己的判断

看到 AI 在几分钟内做出报告，可以先找出自己真正需要的条件：材料有没有读全，关键结论能否核实，格式是否便于继续修改，最终给谁使用。演示只展示了某一次结果，你的任务还可能有别的材料、例外和责任要求。

试用时可以准备三种小样：正常材料、缺了一项信息的材料、带有相互冲突表述的材料。正常小样看它能否完成基本整理；缺项小样看它会不会编造；冲突小样看它能否把分歧留给你确认。小样通过只是继续尝试的理由，还需要观察实际使用中的新情况。

评价不必从一个总分开始。写四句话通常更有用：“它在哪一步帮了忙；哪一步我花了更多时间；发现了什么错误；下一次是否还会用。”一个工具在解释概念上适合你，未必在文件处理上也适合；一次出错也不能据此断言所有用途都无效。

### 普通人现在需要理解到哪一步

初学时，能区分生成、查找和执行，能把问题说清楚，能核对关键事实，就已经有了开始练习的基础。继续深入时，由实际困难决定：看不懂计算就补数据知识，重复操作太多再考虑自动化，想研究模型再学数学与训练。

不要把工具学习变成一张无限清单。你可以给每次尝试设一个具体完成点，例如“从这份材料提取五个字段，并亲自核对”。完成以后得到的是一次使用经验，再据此决定下一步；不会因为没有了解所有模型名称而失去开始的资格。

**今天可做：** 把一项任务分成“能检查的小步骤”和“目前缺少判断依据的部分”。

**可以怎样检查：** 每项判断都有实际任务或样例；无法核实的部分没有因为生成很快而被当成事实。
